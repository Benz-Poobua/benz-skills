# code-notebooks

A notebook is a check, not a picture: one that is not executed is not a check, and a claim without an
assert is an opinion. Notebooks walk a workflow step by step: input -> operation -> output -> check.

## Rules

- **Generated, never hand-edited.** `scripts/build_<name>_nb.py` (nbformat) writes `notebooks/<name>.ipynb`.
  Edit the generator and re-run it. Hand-authored legacy notebooks stay as they are until rewritten.
- **Executed clean.** `jupyter nbconvert --to notebook --execute --inplace notebooks/<name>.ipynb`
  (or the repo's `make nb`); 0 errors before anything is quoted. In a venv whose scripts carry stale
  shebangs, call `<env>/bin/python -m jupyter`.
- **Every claim**: `print("[A3] <what is claimed> = <value>")` **and** `assert <condition>, "<message>"`.
  Each notebook writes `results/nb/<name>_gates.json`; quoted numbers go through the tracer (`benz:paper-numbers`).
- **Theory in the markdown, step by step**: define every symbol, derive the equation, cite the source with
  page and equation number (`benz:paper-read`), state assumptions and the regime where the method holds.
- **Reproducible**: the house rcParams block in the first code cell (`benz:code-house-style`), seeds fixed,
  paths relative to the repo, no hidden state (cells run top to bottom), data read-only.
- **Small outputs**: no giant arrays printed; animations through `to_jshtml()` inside
  `mpl.rc_context({"savefig.dpi": 100})` (jshtml frames use `savefig.dpi`, 300 by default: 5x bloat).

## Structure of a generated notebook

```
# <Title> — <one-line purpose>
> Data: <paths> | Config: <file> | Env: <venv> | Generated by scripts/build_<name>_nb.py — do not edit
## (A) <first step: load / inspect>            markdown theory -> code -> figure -> [A1..] print+assert
## (B) <next step>                              ...
## (Z) Summary                                   table of every gate id with its value; write gates JSON
```

Completion: the generator runs, the notebook executes with 0 errors, every gate id appears in the JSON,
and the book link (if the notebook supports a book section) is refreshed with
`mypaper/mybible/scripts/link_notebooks_to_book.py --write`.
